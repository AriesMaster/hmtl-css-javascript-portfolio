Full-Stack Software Engineering Case Study

BrightSmile Dental

A full-stack dental practice management application developed using Angular, ASP.NET Core 10 Web API and PostgreSQL. The system combines responsive frontend interfaces, patient registration, JWT authentication, role-based access control and appointment management. It includes public-facing dental pages, protected dashboards for Administrators, Dentists and Patients, and backend workflows for scheduling, service management and appointment status updates.

01 / Project Overview

Building a Role-Based Dental Platform

BrightSmile Dental is a full-stack portfolio application designed to demonstrate the development of a real-world, role-based business system. The Angular frontend includes public website pages, patient registration, authentication, protected dashboards and appointment-booking interfaces. The ASP.NET Core backend provides RESTful APIs, JWT authentication, role-based authorization, profile management, dental service management and appointment scheduling. PostgreSQL, hosted through Supabase, provides relational data persistence using Entity Framework Core. The Angular frontend and ASP.NET Core backend are deployed and connected in production. The portfolio application continues to receive feature updates and engineering improvements.

04 / Security

Authentication & Authorization

Authentication establishes user identity, while role-based authorization and ownership checks determine which operations are permitted.

JWT Authentication

After successful login, the backend issues a JSON Web Token containing identity and role claims. The Angular application uses its authentication service to manage the authenticated session and redirect users to the appropriate dashboard. Protected backend endpoints validate the bearer token before processing requests.

Role-Based Access Control

Admin, Dentist and Patient roles have different permissions. Angular route guards control frontend navigation, while server-side authorization enforces API permissions. Additional ownership checks restrict access to appointments belonging to other users.

06 / Appointment Management

Appointment Scheduling & Lifecycle

Appointment management introduces business rules beyond basic CRUD, including scheduling conflicts, ownership checks and controlled status transitions.

Appointment Booking

Patients can book appointments with a selected dentist and dental service. The backend checks whether the requested time overlaps with an existing active appointment.

  • Future appointment date validation
  • Dentist and service validation
  • 30-minute appointment windows
  • Overlapping booking prevention
  • Adjacent time slot support

Rescheduling & Cancellation

Patients can reschedule their own pending appointments and cancel eligible bookings. Cancelled appointments release their reserved time slots.

  • Patient ownership verification
  • Conflict checks during rescheduling
  • Cancellation workflow
  • Rebooking cancelled time slots
  • HTTP 409 responses for conflicts

Appointment Status Management

Authorized dentists and administrators can update appointment statuses according to defined business rules.

  • Pending to Confirmed
  • Confirmed to Completed
  • Eligible appointments to Cancelled
  • Invalid transitions rejected

Database Transaction Handling

Scheduling mutations use PostgreSQL transactions and dentist-specific advisory locks to coordinate appointment changes. This is designed to reduce the risk of simultaneous conflicting bookings.

Dedicated concurrent-request testing is still planned.

Scheduling Conflict Test

With an existing 09:00 appointment, a booking request at 09:15 was rejected with HTTP 409. A booking at 09:30 was accepted with HTTP 201, demonstrating the intended 30-minute slot boundary behavior.

Cancellation & Rebooking Test

Appointment cancellation returned HTTP 200 and changed its status to Cancelled. A new booking for the same time subsequently returned HTTP 201.

09 / Problem Solving

Engineering Challenges & Lessons

Preventing Double Bookings

Comparing appointment timestamps for exact equality was insufficient because partially overlapping appointment windows could still be accepted. The scheduling logic was improved to detect overlapping 30-minute appointment intervals.

Authentication vs Authorization

A valid JWT proves user identity but does not grant unrestricted access. Angular route guards improve navigation control, while backend role checks and appointment ownership validation enforce permissions.

Frontend Integration

Integrating Angular with a separately developed REST API requires consistent request models, response handling, authentication state and navigation. The application uses shared services and role-specific feature components to organize this integration.

Database Reliability

A transient PostgreSQL connection failure occurred during local testing. Retrying succeeded, highlighting the importance of distinguishing infrastructure issues from application logic defects.
