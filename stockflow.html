StockFlow

StockFlow helps small hardware stores track supplier orders, record partial deliveries, and see what stock is on hand and what’s still due.

Imagine a hardware store tracking supplier orders in a spreadsheet and deliveries on paper notes. When only 12 of 20 boxes of screws arrive, staff have to check both records to see what’s on the shelf and what’s still due. StockFlow brings the order, its deliveries, and the stock changes together in one place.

Project Overview

Tracking Orders and Stock as Goods Arrive

An order can arrive in several deliveries. For each delivery, the business needs to know what arrived, what remains outstanding, and how much stock is on hand.

Purchase Orders

The workflow starts with a draft order containing products and quantities. Approval makes the order eligible to receive stock.

Goods Receiving

Each delivery records the quantities received against the original order lines. The outstanding quantity guides what can be received next.

Inventory Tracking

Each receipt line is designed to produce a stock movement and update the product’s on-hand balance. The movement history records where the change came from.

System Architecture

Angular, Spring Boot and PostgreSQL

Angular is the user interface. Spring Boot hosts the Java domain model and the planned REST endpoints. PostgreSQL stores orders, receipts, balances, and stock movements.

Angular Frontend

The public site, login form, signal-based authentication store, HTTP interceptor, route guards and responsive protected workspace are implemented on the authentication feature branch. Real sign-in and business API integration remain pending.

Java Domain Model

The model handles order state transitions and quantity validation. Typed exceptions and problem-detail mapping are in place for business-rule failures.

Relational Model

Flyway V1 defines the business schema; V2 adds four authentication tables. Product, user, session and refresh-token JPA persistence is implemented. Remaining business mappings and receipt transactions are planned.

Purchase Order Workflow

Receiving 12 of 20 Boxes of Screws

A hardware store orders 20 boxes of screws, and the supplier delivers 12. The store can add 12 boxes to its on-hand stock and see that 8 are still due.

Approve the Draft

The Java domain model allows a draft order to be approved before it can receive stock. The planned Angular screen will show the current order state and available actions.

Record a Partial Delivery

In the planned persistence workflow, recording the delivery creates a stock movement of +12 boxes and leaves the order partially received. A follow-up receipt for 9 boxes is invalid because only 8 are outstanding.

View Domain Rules View JUnit Tests

Handle Retries and Concurrent Deliveries

The receipt design uses one database transaction for receipt lines, order quantities, inventory balances, and stock movements. An idempotency key is planned to keep a retried request from counting stock twice. Database locking is planned to protect concurrent updates.

Engineering Decisions

Security by Design

Authentication foundations are implemented on feature branches; HTTP integration and production hardening remain in progress.

Spring Security & Argon2id

Database-backed credential verification uses salted Argon2id hashes rather than plaintext or reversible encryption. Four roles model administration, purchasing, approval and warehouse responsibilities.

JWT & Session Lifecycle

Signed 15-minute access tokens, seven-day sessions and SHA-256 refresh-token digests. Transactional rotation uses a pessimistic session lock and revokes a session on detected reuse. PostgreSQL concurrency verification is pending.

Angular Security Boundary

Signals keep access tokens in memory. The interceptor restricts token attachment to relative API paths; guards control navigation. Server-side authorization, HttpOnly refresh cookies and CSRF integration remain pending.

Testing and Verification

Domain Rules and Database Setup

Local verification on 25 November 2026: 31 backend JUnit tests and 20 frontend Vitest tests passed. Both Flyway migrations were validated against development PostgreSQL; Hibernate schema validation and Angular production compilation succeeded. These results are not end-to-end or production certification.

Verified Automated Tests

JUnit covers domain rules, password hashing, credential verification, JWT validation and session primitives. Vitest covers authentication state, interceptor behavior and guards.

Persistence and API Tests

Planned tests cover persisted quantities, invalid receipts, rollback, duplicate requests, and concurrent delivery updates.

End-to-End Verification

Once the screens and API are connected, verify a draft through approval and partial receiving, including the outstanding quantity and the resulting stock movement.
