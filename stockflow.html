StockFlow

A stock and purchase order management system for a small business. StockFlow is designed to track approvals, partial deliveries, outstanding quantities, and the stock movements created when goods arrive.

Project Overview

Tracking Orders and Stock as Goods Arrive

An order can arrive in several deliveries. For each delivery, the business needs to know what arrived, what remains outstanding, and how much stock is on hand.

Purchase Orders

The workflow starts with a draft order containing products and quantities. Approval makes the order eligible to receive stock.

Goods Receiving

Each delivery records the quantities received against the original order lines. The outstanding quantity guides what can be received next.

Inventory Tracking

Each receipt line is designed to produce a stock movement and update the product’s on-hand balance. The movement history records where the change came from.

System Architecture

Angular, Spring Boot and PostgreSQL

Angular is the user interface. Spring Boot hosts the Java domain model and the planned REST endpoints. PostgreSQL stores orders, receipts, balances, and stock movements.

Angular Frontend

The responsive public homepage, navigation, footer, and routing are implemented. Angular’s HTTP client and development proxy are configured for future integration with the purchase order and inventory screens.

Java Domain Model

The model handles order state transitions and quantity validation. Typed exceptions and problem-detail mapping are in place for business-rule failures.

Relational Model

Flyway creates seven tables. Order lines reference products, receipt lines fulfil order lines, and each receipt line can produce one stock movement. JPA mappings and repositories are planned.

Purchase Order Workflow

Receiving 12 of 20 Units

Consider an approved order for 20 units. The first delivery contains 12, leaving 8 outstanding. The next delivery can contain up to 8 units.

Approve the Draft

The Java domain model controls which state transitions are allowed. The planned Angular screen will display the current order state and the actions available for it.

Record a Partial Delivery

In the planned persistence workflow, receiving 12 adds 12 to on-hand stock, records a movement of +12, and leaves the order partially received. A follow-up receipt for 9 is invalid because only 8 units are outstanding.

Handle Retries and Concurrent Deliveries

The receipt design uses one database transaction for receipt lines, order quantities, inventory balances, and stock movements. An idempotency key is planned to keep a retried request from counting stock twice. Database locking is planned to protect concurrent updates.

Testing and Verification

Domain Rules and Database Setup

JUnit tests cover purchase order business rules. Flyway’s initial migration has been applied and validated on the development PostgreSQL database, and Spring Boot Actuator returned an UP health response locally.

Persistence and API Tests

Planned tests cover persisted quantities, invalid receipts, rollback, duplicate requests, and concurrent delivery updates.

End-to-End Verification

Once the screens and API are connected, verify a draft through approval and partial receiving, including the outstanding quantity and the resulting stock movement.
